# Durable account pictures and once-ever scenes

## Intent

Accepted explicit chat/API image work must survive a closed tab or core restart without spending another provider attempt. A completed picture must reach the archive once or report an honest recoverable archive failure. A once-ever character scene must exist completely in durable history before its trigger is consumed, regardless of live pacing or disconnect.

## Account picture design

- Add an existing-PostgreSQL request journal (new migration210) for explicit chat/API account pictures: immutable request UUID, authenticated user, canonical payload/digest, safe archive metadata, phase, memory ID and timestamps. Persist before any native provider call. Store only the explicit request plus existing local appearance composition, never fetched conversational history, private auth or reference bytes.
- Separate accepted jobs from WS-scoped task cancellation. Own worker tasks at application lifespan, with bounded concurrency and clean shutdown. User/device disconnect affects delivery, not accepted generation. Startup resumes recovery of known IDs, not new generation.
- Extend the private worker with a strictly read-only recovery operation for an existing exact request payload/hash. It may return the cached completed bytes or sanitized pending/failed/unknown status; it must never claim, rotate, render or fail over. Keep authentication, owner allowlist, Commander reference privacy, bounds and conflict validation identical to generation. Wrong user/payload cannot retrieve another claim. Do not reveal prompts/paths/provider diagnostics in public errors.
- Core generation accepts an explicit durable request ID. Once submission may have happened, recovery uses only the read-only operation. Unknown/pending/ambiguous outcomes never automatically resubmit, create another ID or consume another account operation. Policy refusals never fail over; existing one eligible service-error failover stays inside the worker's original claim. A crash before initial submission may conservatively require explicit user action; do not claim impossibly atomic DB-to-native dispatch.
- Archive with a stable request-linked memory identity and concurrency-safe idempotency. Retrying archive after file/DB failure retrieves the same cached output, never rerenders or creates duplicate memories. Do not delete or overwrite an existing unrelated archive entry. Preserve original PNG and derived WebP/thumbnail contracts. Avoid annotation-based dedup falsely dropping a distinct requested picture; request-ID dedup is the relevant contract.
- Report generated, archived and uncertain/failure states truthfully. `save_image` returning None cannot count as archived success on chat or API. Expose authenticated status by ID and optional idempotent API request key; same key with changed payload is a conflict. Reconnect can discover pending/completed work or see its saved gallery item. If replaying live image events, include stable request/memory ID and deduplicate in client; exactly-once archival does not imply exactly-once network delivery.
- Scope is explicit account chat/API pictures. Preserve local/development APIs and existing Her POV no-reclaim guard; coordinate any shared worker/client interface changes with those callers. Do not silently add automatic recovery generation to Her POV or any other path.

## Once-ever oath design

Use one PostgreSQL transaction to claim `companion_firsts(user_id,oath_fulfilled)` and append the full configured scene into the user's durable conversation history, updating message counts consistently. If no appropriate conversation exists, create a valid parent within that transaction. On any DB failure, roll back trigger and scene together. Concurrent calls must yield one complete historical scene. After commit, pace live sends with persistence disabled so they cannot duplicate history. Cancellation then only stops animation; history remains complete on reconnect. Existing consumed triggers are respected exactly as found: do not infer, delete, reset or replay prior owner events. Empty/invalid scene data does not consume a trigger.

## Acceptance

Hold renderer, disconnect/reconnect; core restart after worker completion before archive; archive DB failure then recover; duplicate same request with matching and mismatched payload; concurrent archive attempts; wrong user/ref/prompt-privacy cases; unknown/pending/refusal never call renderer on recovery. Real worker Unix HTTP fixture and disposable PostgreSQL/filesystem tests are preferred. Oath: cancel after each live line, concurrent connections, parent/line/commit failure and existing-trigger cases; complete history once, no lost trigger. No real provider/image generation, production DB, GPU or new service spend for implementation tests.
