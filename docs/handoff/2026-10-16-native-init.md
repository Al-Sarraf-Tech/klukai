# Native offline builds use a source-bound namespace init

The offline Bubblewrap command uses `--as-pid-1` with a small first-party init mounted read-only at `/run/klukai-native-init.py`. The init launches the actual command as its child, waits for the initial child and every adopted descendant, and permits success only after `waitpid` proves ECHILD and all observed statuses were naturally zero. A detached persistent child therefore keeps the command alive until the original host-supervisor deadline. Nonzero, signal, launch failure, interruption or unknown state fails.

This replaces Bubblewrap's optional PID1 forwarding reaper, whose eventfd success notification can let its outer monitor exit before the reaper settles. The bounded delayed-eventfd control reproduced outer0/reaper-9 with no injected status or signal. A prior attempt to run the workload itself as PID1 was rejected: namespace teardown hid a persistent child's outcome. The first-party init addresses that boundary by keeping PID1 alive through complete child settlement. Original failed bridge01 remains failed and unselected; its historical child's identity/sender was not retrospectively established.

The trusted base CPython executable is selected from the active CPython's explicit base executable, resolved under its allowed base prefix, hash-bound and probed for matching minor/SOABI. There is no PATH search or generic `python3` fallback. The init file is a declared bootstrap input and executing helper, checked through normal source binding before/after execution and selection, including component consumers. The imported init digest is frozen and compared again before each identity/mount/unchanged check; this complements selected committed-source equality and the read-only mount without claiming atomic protection against a same-UID filesystem attacker. The exact init and interpreter identities are retained in the sandbox manifest. Only the init file is additionally mounted; no repository directory is exposed.

Generic process/supervisor bytes, original deadline, caller pidfd, all-zero admission, bounded cancellation/cleanup, Bubblewrap parent-death protection, namespaces/network isolation, mount restrictions, clear environment, capabilities and session flags remain unchanged. The init refuses execution outside Linux PID1 and malformed payloads with explicit checks that remain active under optimized Python. It uses only stdlib and executes argv directly. Payload spawn restores Python-ignored SIGPIPE/SIGXFZ/SIGXFSZ defaults, matching the original exec boundary, and preserves the inherited signal mask. Signals/interruption fail immediately; namespace teardown on that failure cannot turn it into success.
