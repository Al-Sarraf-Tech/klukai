# Grok account-login compose comments: recovery plan

## Data preserved

`docker-compose.yml` changes comments only. The core service, networks,
volumes, and environment keys are unchanged. No database or application
data is removed. The image worker is host state outside this file
(`klukai-agy-images.service` and `~/.config/klukai/agy-images.env`).

## Rollback

Deploy-on-merge restores the previous web release, then the core image,
then the checkout. That puts the previous comments back. It does not
restart the image worker. The previous core still speaks the worker
socket for pictures and does not call `POST /complete`, so a worker left
on the Grok unit remains usable. To return the worker to the previous
unit, pause the deployer, restore that unit from the previous checkout,
and restart `klukai-agy-images.service`. Do not print the env file.

## Verification

Confirm the pinned image ID, core readiness, and the read-only `claude`
test-user checks. Then run `ops/amarillo/scripts/klukai-grok-smoke.py`
once: one render, a passing checker, a ledger row, and a chat turn
reporting `model=grok-4.7` and `effort=medium`.
